# Noch zu bestätigende Projektentscheidungen

Diese Punkte blockieren M0 nicht; die Architektur verwendet sichere Defaults.

1. endgültiger Repository-/Paketname;
2. öffentliche Code-Lizenz vor erstem Release;
3. zuerst Casual-Completion oder cEDH-Completion als Produktfokus;
4. welche TopDeck-/Spicerack-Nutzungsbedingungen akzeptiert werden;
5. ob private User-Decks Training verlassen dürfen;
6. Preisquelle und erlaubte Speicherung, falls Budget früh benötigt wird;
7. Forge-Bridge im separaten Repo oder als kleiner Adapter in beiden Repos;
8. öffentliche Dataset-Veröffentlichung oder nur Build-Skripte/Manifeste.

## Defaults dieser Baseline

- separates Repo;
- cEDH als messbarer Performance-Zweig, aber Completion-Benchmark formatübergreifend;
- keine permission-gated Source;
- kein Preisfeature vor explizitem Source-Review;
- File Bridge statt RPC;
- Build-Skripte veröffentlichen, Fremddaten nur bei Redistribution-Freigabe.
